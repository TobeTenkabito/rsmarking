# Agent 工作区

Agent 页采用左侧会话列表、右侧消息和底部输入框。刷新前端并重启 AI 网关后生效；无需修改模型密钥。

## 对话与输入

- 消息支持 GFM Markdown：标题、表格、嵌套列表、任务列表、引用、代码块、链接和删除线。分析模式的报告也使用同一渲染器。
- HTML 作为文字展示，经过 DOMPurify 清洗；不自动加载模型文本里的远程图片。生成图片和附件仍使用已有预览功能。
- 默认 Enter 发送，Ctrl/Command + Enter 换行；输入框下方可切换为 Ctrl/Command + Enter 发送、Enter 换行。Shift + Enter 始终保留普通换行；中文输入法选词不会发送。偏好保存在浏览器本地。
- 历史列表支持搜索、恢复和删除。发送及收到回复后自动保存，同一对话使用稳定 ID 更新；网络失败显示重试入口，失败时新建/切换不会丢弃当前对话。
- 悬停历史会话，点击旁边的铅笔可编辑标题（最多 120 字符）与注释（最多 4000 字符）。注释以较小字体直接显示在标题下方，默认缩略为两行；点击展开全文，鼠标移出该会话后收起，也支持键盘与手机点按。搜索同时匹配标题和注释。自定义标题与注释保存在后端，继续聊天的自动保存不会覆盖它们；注释不作为模型消息发送。
- 单个存档最多保留最近 500 条消息；单条正文最多 100000 字符，超限明确报错，不再静默截断。历史显示与模型上下文窗口是两回事。
- 模型请求进行中不能切换或删除会话，以防回复写入另一会话。关闭弹窗不会终止正在运行的后台请求。
- 消息直接展示，不再用人为逐句延迟伪装流式输出。工具步骤默认折叠，可展开查看错误及结果状态。
- 可以复制回复；浏览器不允许剪贴板访问时仍可手动选择文字。

## 置顶、导入导出与分支

- 会话旁的 `⋯` 菜单提供置顶/取消置顶、导出、分支及删除。置顶会话始终排在普通会话之前，多个置顶按置顶时间排列；刷新、重启及继续聊天都会保留状态。置顶只影响列表展示，不自动加入模型记忆。
- 左侧“导入聊天”接收本应用导出的 JSON 文件，最大 20 MB、500 条消息。导入成功后自动打开独立的新会话，保留标题、注释、置顶状态、消息和可用的附件信息，不覆盖原有会话或沿用文件中的会话 ID。
- “导出聊天”下载单个会话 JSON，可作为备份再次导入。格式标识为 `rsmarking.conversation`，版本为 `1`，内容放在 `conversation` 对象中。支持本应用格式，不直接支持其他聊天产品的导出包。
- 导出包含聊天正文、工具步骤、附件中已保存的文本摘录及内嵌图片。生成文件仅保留本部署的资源引用，不打包文件本体；迁移到其他部署时，需要另行保存这些文件。导入不加载外部图片 URL，也不接受 `system` 或 `tool` 角色作为消息。
- 会话菜单中的“分支到新聊天”复制整段已保存对话；每条消息下方的“从这里分支”只复制到该消息为止（包含该消息）。新分支使用独立会话 ID，继承标题及注释，默认不置顶；后续回复、重命名、删除不会修改原对话。
- 分支会恢复已有文本上下文，不重新执行历史工具，也不复制地图数据或生成文件。模型仍受已有上下文长度限制。发送请求进行中会阻止切换与创建分支；失败时保留当前对话。

## 工具授权与账户鉴权的区别

API Key 负责向模型供应商鉴权。本次调整的是本应用的 **工具执行授权**，不能关闭供应商自身的策略。原来 `agent_security.py` 要求当前提示词逐项命中工具关键词；例如“分析影像并制作报告”可能不包含中间所需的 MNDWI 工具名，因此被应用拦截。

标准模式可为明确的分析、计算、实现等任务直接调用 `run_script_sandbox`，无需用户逐次说出“脚本”或切换完全控制，也不依赖“自动完成任务所需步骤”开关。显式请求“允许使用沙箱”也可授权该工具。这里只开放项目现有的隔离计算沙箱，未开放主机终端或项目源码写入。

设置中的“自动完成任务所需步骤”显式发送 `allow_task_steps=true`。对于当前明确的行动任务，它进一步允许其他已知内置工具完成必要处理和新建输出，不要求用户逐一说出工具名。该选项不能提升权限等级、覆盖明确禁止事项，也不会自动授权未知扩展工具或额外的图像生成付费请求。

同一活动会话中的“继续吧”“继续分析”“按刚才方案执行”和参数调整会沿用服务端记录的用户任务，仅用于处理和新建输出；修改、删除仍检查本轮指令。新任务会替换旧目标，但明确禁止事项独立保存，不会因换一种续接表达、压缩历史或服务重启而消失。只读模式始终阻止沙箱。禁止事项目前保留到删除/重置会话，改变这些限制请新建会话。

助手回复、附件、检索数据不会写入授权记录。恢复本会话时保留服务端已有检查点；导入历史、创建分支或恢复没有检查点的旧存档仅提供上下文，不从历史文本重新授予权限，此时应说明当前要执行的任务。

| 权限 | 行为 |
| --- | --- |
| 只读 | 查询、查看、解释；不执行处理或写入 |
| 安全操作 | 允许必要处理和新建输出，不更新、删除现有数据 |
| 标准（默认） | 可直接使用隔离沙箱；其他必要处理、新建受自动步骤开关控制；更新仍须明确授权，删除须明确且有具体对象 |
| 完全控制 | 现有的项目数据自主操作权限；仍尊重禁止事项和沙箱边界 |

关闭“启用项目工具”会发送空工具列表，后端不会把它误当成默认启用全部工具。附带工作区信息和跨会话记忆分别控制；跨会话记忆默认关闭，自动保存本身不代表允许引用其他聊天。

以上不是多用户登录/租户隔离系统。现有服务仍沿用项目的部署与访问边界，历史存储也是当前部署共享的。若未来部署给多个用户，需单独设计身份、会话所有权与数据权限，不能把前端权限选择器当作登录鉴权。

## 多轮上下文与中断恢复

- 每次请求组合当前目标、近期补充要求、独立禁止事项、最近对话、较早对话摘要、附件引用和工具结果摘要。默认直接参考最近 12 条消息；活动窗口保留 20 条，移出的消息生成带全文引用的首尾摘录。这是提取式摘要，不使用额外模型调用，也不保证摘要包含原文的每个细节。
- 原始消息、附件及工具结果保存到 `storage/ai_agent_state.sqlite3`。模型可通过只读工具 `read_session_context` 搜索当前会话、按引用分页读取原文；它不能读取另一会话的引用。最近的工具结果摘要单独保留输出 ID、名称等字段，减少后续任务丢失生成结果的问题。关闭项目工具后也会关闭此回查工具。
- 附件文本与内嵌图片会持久保留；后续没有新图片的请求自动附带最近两张历史图片。较早图片可按附件引用重新读取。服务器保存的是上传时已提取的文本和图片，并非原始附件文件的完整备份。
- 每次调用模型前检查输入预算，包括消息与工具定义。`AI_CONTEXT_TOKEN_BUDGET` 默认 `131072`，使用保守的 UTF-8 字节估算，每张图片另预留 4096；这不是各供应商精确的 token 计数。它与 `AI_MAX_TOKENS` 输出预算分开，使用较小上下文的模型时须降低输入预算并减少工具，给输出留足空间。
- 超出预算时先压缩参考材料和工具结果，再移除较早的完整工具调用/结果组及次要参考块。系统规则与当前请求不截断，工具调用与结果保持配对；必要内容仍超限则明确报错。全文依旧可回查，长对话无需把所有内容每轮全部重发。
- 用户消息和附件在调用模型前保存，具有副作用的工具先保存执行意图、完成后保存结果。如果工具完成后模型超时，返回已执行步骤并保留未完成任务；点击“重试本次请求”复用请求编号、更新原回复，不重复添加一轮消息。刷新页面后也可发“继续分析”恢复未完成任务。
- 同一未完成任务内，相同工具及规范化参数的已成功操作复用结果。已完成请求也按请求编号缓存响应，避免响应丢失后的重复执行。若进程在工具运行中退出而执行结果未知，恢复时阻止新增写操作，先查看已有输出再明确发起新任务；不能承诺外部操作在任意崩溃时都恰好执行一次。
- 六小时 TTL 仅清理内存缓存，持久记录在重启后仍可恢复。删除历史会话会清理该会话的检查点、上下文资源和请求缓存，生成的项目文件不随之删除。持久数据没有自动按时间清除，部署维护时应纳入磁盘用量与备份管理。

会话执行锁目前在单个 AI 网关进程内生效。SQLite 对单个工具意图提供原子登记，但完整会话并发尚未使用分布式锁；当前应使用单个 AI 网关工作进程，不应据此宣称支持多进程同时修改同一会话。

## 插件扩展边界

本轮保留 `function_registry.py` 的 `RegisteredFunction` 作为扩展点，没有加入远程插件市场或让模型下载安装代码。服务端新增工具需声明 Pydantic 参数、处理函数、工具效果和允许的权限；经过审核后再注册。未知工具不会自动继承“自动完成任务步骤”的授权。跨供应商调用仍使用统一的 function calling 协议。

## 维护与验证

Markdown 库锁定在根目录 `package.json` / `package-lock.json`；浏览器加载 `client/vendor/markdown/` 中本地副本，不依赖新的 CDN。升级后执行 `npm run vendor:markdown`，并提交库文件和许可证。

```sh
npm test
npm run test:ui
python -m pytest tests/unit/services/test_ai_agent_security.py tests/unit/services/test_ai_agent.py tests/unit/services/test_ai_conversation_archive.py tests/unit/services/test_ai_conversation_transfer.py tests/unit/services/test_ai_context_recovery.py -q
```

浏览器测试使用本机 Edge 的无头模式和隔离的模拟 API，不读取 `.env`，不消耗模型额度。测试服务器只提供公开前端模块和测试页面，不暴露仓库数据或密钥。截图在 `test-results/`；若环境没有 Edge，可在 Playwright 配置中改用已安装的 Chromium。
